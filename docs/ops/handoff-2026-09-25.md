## Deploy incident & script safeguard

- **Incident 2026-09-25:** `railway up --detach` was run from the wrong
  checkout directory, uploading Crest's `Dockerfile` (containing
  `requirements.txt`, Python app with dependencies) instead of
  backlog-works' minimal stdlib-only image. Caught by generated-domain
  deploy log review; original `railway.json` and `app/main.py` caught the
  mistake, but the damage was the multi-hour deploy re-run needed to
  recover.
- **Guard added:** `scripts/deploy.sh` now the only deploy path. Script
  resolves repo root from its own location, validates `railway.json` and
  `app/main.py` presence (aborts with clear error if either is missing in
  the resolved checkout), fetches `RAILWAY_PAT` from Bitwarden inline
  (never echoed or printed), runs `railway up --service backlog-works
  --detach`, and polls `https://backlog.works` for 6 minutes (20s intervals)
  until a `200` status is seen, then prints final status and `/healthz`
  body. **Must always be run from this checkout** (`scripts/deploy.sh`'s
  `cd` ensures root-relative paths are valid).
- **DNS note:** Railway's custom-domain provisioning is automatic for
  domains purchased through Railway's registrar — no extra PO DNS access
  needed. Domain state is observable via `railway domain status` (does not
  require API token escalation, only project scope) and the Railway web UI
  account settings.
- **Updated AGENTS.md:** added hard rule under Infrastructure Facts to
  document the incident and the script-only requirement.
